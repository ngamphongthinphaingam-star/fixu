# FixU – ระบบแจ้งและติดตามปัญหาภายในมหาวิทยาลัย

เว็บแอปให้นักศึกษา/บุคลากรแจ้งปัญหาอาคารสถานที่ (ไฟเสีย แอร์เสีย น้ำรั่ว ฯลฯ) พร้อมรูป ระบุอาคาร/ห้อง และติดตามสถานะ ส่วนเจ้าหน้าที่รับงาน มอบหมาย และปิดงาน
ระบบหลังบ้านตรวจสิทธิ์ทุกคำขอ เก็บข้อมูลใน PostgreSQL (Supabase) และ deploy บน Vercel ได้

**สารบัญ:** [1 ต้องมีอะไรบ้าง](#1-ต้องมีอะไรบ้าง) · [2 ลองบนเครื่องตัวเอง](#2-ลองบนเครื่องตัวเอง-10-นาที) · [3 ขึ้นออนไลน์](#3-ขึ้นออนไลน์-supabase--github--vercel) · [4 วิธีใช้งาน](#4-วิธีใช้งานระบบ) · [5 แก้ปัญหา](#5-แก้ปัญหาที่พบบ่อย) · [6 ดูแลระบบ](#6-การดูแลระบบ) · [7 ก่อนใช้กับข้อมูลจริง](#7-ก่อนใช้กับข้อมูลจริงของมหาวิทยาลัย)

## 2. ลองบนเครื่องตัวเอง (~10 นาที)
วิธีนี้ **ไม่ต้องมี Supabase/Vercel** ข้อมูลเก็บในโฟลเดอร์ `data/` ของเครื่องคุณ เหมาะดูว่าระบบทำงานอย่างไรก่อนขึ้นออนไลน์

1. ติดตั้งแพ็กเกจ: `npm install`
2. คัดลอก `.env.local.example` เป็นไฟล์ชื่อ **`.env`** (Windows: `copy .env.local.example .env` · Mac/Linux: `cp .env.local.example .env`)
3. เปิด `.env` แล้วแก้ `ADMIN_EMAILS=` เป็นอีเมลของคุณ (ใช้อีเมลอะไรก็ได้ในโหมดนี้)
4. รัน: `npm run dev` ควรเห็นข้อความ “FixU พร้อมที่พอร์ต 3000”
5. เปิดเบราว์เซอร์ที่ **http://localhost:3000** → กรอกอีเมลที่ตั้งเป็น `ADMIN_EMAILS` กับชื่อ → เข้าสู่ระบบ คุณจะเป็น **ผู้ดูแลระบบ**
6. ลองหลายบทบาท: เปิดหน้าต่างไม่ระบุตัวตน (Incognito) อีกอัน เข้า http://localhost:3000 ด้วยอีเมลอื่น (เช่น `student@example.com`) จะเป็น **ผู้แจ้ง** แล้วกลับมาหน้าต่างแรก เมนู **จัดการผู้ใช้** เปลี่ยนอีกอีเมลเป็น **เจ้าหน้าที่** ตามที่ต้องการ (ดูขั้นตอนใช้งานจริงในหัวข้อ 4)
7. หยุดระบบด้วย `Ctrl + C` · ล้างข้อมูลทดลอง: ลบโฟลเดอร์ `data/`

ชุดทดสอบอัตโนมัติ: `npm test` (ควรผ่านทั้งหมด)

## 3. ขึ้นออนไลน์ (Supabase + GitHub + Vercel)
ใช้เวลาประมาณ 30–45 นาทีครั้งแรก ทำตามลำดับ

### ขั้น A — สร้างฐานข้อมูลที่ Supabase
1. เข้า supabase.com → **New project** ตั้งชื่อ เลือกภูมิภาคใกล้ไทย (เช่น Singapore) ตั้ง **รหัสผ่านฐานข้อมูล** (จดไว้ — ลืมแล้วรีเซ็ตได้ที่ Project Settings → Database)
2. รอโปรเจกต์สร้างเสร็จ → เมนูซ้าย **SQL Editor** → New query
3. เปิดไฟล์ `db/schema.sql` ในโฟลเดอร์นี้ คัดลอกทั้งหมดไปวาง → กด **Run** (ต้องขึ้น Success) นี่คือการสร้างตารางและเปิด RLS รันซ้ำได้ไม่เสียหาย รวมถึงตารางหมวดหมู่หน่วยงานผู้รับผิดชอบและรายการห้องที่ผู้ดูแลจัดการได้
4. หาสตริงเชื่อมต่อ: กดปุ่ม **Connect** (หรือ Project Settings → Database → Connection string) เลือกแบบ **Transaction pooler** (พอร์ต 6543) แล้วคัดลอก หน้าตาประมาณ `postgresql://postgres.xxxx:[YOUR-PASSWORD]@aws-0-ap-southeast-1.pooler.supabase.com:6543/postgres`
5. แทน `[YOUR-PASSWORD]` ด้วยรหัสผ่านจริง **ถ้ารหัสมีอักขระพิเศษ** (เช่น `@ # / :`) ต้องแปลงเป็น URL-encode ก่อน (เช่น `@` เป็น `%40`) — แนะนำตั้งรหัสที่เป็นตัวอักษรและตัวเลขล้วนเพื่อเลี่ยงปัญหา
   *(ชื่อเมนูใน Supabase อาจเปลี่ยนตามเวอร์ชัน ให้หาคำว่า Connection string / Connect)*

### ขั้น B — ขึ้น GitHub
1. เข้า github.com → New repository ชื่อ `fixu` เลือก **Private** (ไม่ต้องติ๊กสร้าง README)
2. รันในโฟลเดอร์ `fixu`:
```
git init
git add .
git status        # ตรวจ: ต้องไม่เห็นไฟล์ .env หรือ node_modules ในรายการ
git commit -m "FixU"
git branch -M main
git remote add origin https://github.com/ชื่อบัญชีคุณ/fixu.git
git push -u origin main
```
**ห้าม** คอมมิต `.env` หรือรหัสผ่านใดๆ (`.gitignore` กันไว้ให้แล้ว)

### ขั้น C — Deploy บน Vercel
1. vercel.com → **Add New… → Project** → Import repo `fixu` (ต้องอนุญาตให้ Vercel เข้าถึง GitHub)
2. **Framework Preset: Other** ไม่ต้องตั้ง Build/Output Command
3. เปิดส่วน **Environment Variables** แล้วเพิ่มตามตาราง:

| ชื่อ | ค่า |
|---|---|
| `AUTH_MODE` | `local` |
| `SESSION_SECRET` | สตริงสุ่มยาว ≥ 32 ตัว สร้างด้วยคำสั่ง `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"` |
| `PILOT_CODE` | รหัสเข้าร่วมที่คุณตั้งเอง ≥ 8 ตัว (แจกให้ผู้ทดสอบ) |
| `ADMIN_EMAILS` | อีเมลผู้ดูแลระบบ (คั่นหลายอันด้วย `,`) |
| `DATABASE_URL` | สตริงจากขั้น A ข้อ 4–5 |
| `GEMINI_API_KEY` | *(ไม่บังคับ)* API key จาก [Google AI Studio](https://aistudio.google.com/app/apikey) เพื่อเปิดผู้ช่วย AI · เก็บเป็น Environment Variable เท่านั้น |
| `GEMINI_MODEL` | *(ไม่บังคับ)* ค่าเริ่มต้น `gemini-3.1-flash-lite` |
| `SMTP_URL`, `MAIL_FROM` | *(ไม่บังคับ)* ถ้าอยากให้ส่งอีเมลจริง เช่น `smtps://user:pass@smtp.host:465` |

4. กด **Deploy** รอจนขึ้นสำเร็จ แล้วเปิดลิงก์ `https://ชื่อโปรเจกต์.vercel.app`
5. ตรวจสุขภาพ: เปิด `…vercel.app/healthz` ต้องได้ `{"ok":true}` (ถ้าไม่ได้ ดูหัวข้อแก้ปัญหา)
6. ถ้าแก้ตัวแปรทีหลัง ต้องกด **Redeploy** เพื่อให้มีผล

ผู้ช่วย AI จะอ่านเฉพาะประเภทและรายละเอียดที่ผู้ใช้ส่งเพื่อเสนอหมวดปัญหา ความเร่งด่วน และคำแนะนำเบื้องต้น ผู้ใช้ต้องติ๊กยินยอมก่อนเรียก AI และควรลบข้อมูลส่วนตัวออกก่อนส่ง ข้อมูลที่ใช้ Gemini API Free tier อาจถูกใช้เพื่อปรับปรุงผลิตภัณฑ์ของ Google ตามเงื่อนไขของผู้ให้บริการ จึงไม่ควรใช้กับข้อมูลจริงที่ระบุตัวบุคคลได้ หากไม่ตั้ง `GEMINI_API_KEY` ระบบแจ้งปัญหาส่วนอื่นยังใช้งานได้ตามปกติ

### ขั้น D — เข้าใช้ครั้งแรก
เปิดเว็บ → กรอก **อีเมลผู้ดูแลระบบ** (ตรงกับ `ADMIN_EMAILS`) + ชื่อ + **รหัสเข้าร่วม** (`PILOT_CODE`) → เข้าสู่ระบบ ระบบจะตั้งคุณเป็นผู้ดูแลระบบให้อัตโนมัติ
จากนั้นแจกลิงก์ + รหัสเข้าร่วมให้ผู้ทดสอบ ใครเข้าด้วยรหัสนี้จะได้บทบาท “ผู้แจ้ง” ส่วนเจ้าหน้าที่ให้ผู้ดูแลตั้งเอง (ดูหัวข้อ 4.1)

หลังจากนี้ ทุกครั้งที่ `git push` ขึ้น `main` Vercel จะ deploy ให้อัตโนมัติ

หน้าเว็บปรับตามขนาดจออัตโนมัติ ใช้ได้บนมือถือ แท็บเล็ต แล็ปท็อป และจอใหญ่ ผ่านเบราว์เซอร์ปัจจุบัน (Chrome, Safari, Edge, Firefox)
| ขนาดจอ | การแสดงผล |

| แท็บเล็ต (701–1024px) | เมนูลิ้นชักเหมือนมือถือ แต่ตารางแสดงเต็ม |
| คอมพิวเตอร์ (≥ 1025px) | เมนูด้านซ้ายแบบถาวร · จอกว้างมาก (≥ 1500px) ขยายพื้นที่เนื้อหา |
- รองรับโหมดมืด/สว่างตามเครื่อง, ลดแอนิเมชันตามการตั้งค่าเครื่อง, และรอยบากหน้าจอ (safe area) ของ iPhone
- **ติดตั้งเป็นแอป (ไม่ต้องผ่าน App Store):** Android/Chrome เมนู ⋮ → “ติดตั้งแอป” · iPhone/Safari ปุ่มแชร์ → “เพิ่มไปยังหน้าจอโฮม” (ต้องเปิดผ่าน HTTPS เช่นลิงก์ Vercel) หมายเหตุ: ยังไม่ทำงานแบบออฟไลน์ ต้องมีอินเทอร์เน็ตเสมอ
- แผนที่: หมุดมีตัวเลขจำนวนเรื่อง บนมือถือกดหมุดหรือเลือกปุ่มอาคารเพื่อดูรายการใต้แผนที่
- ผู้พัฒนาทดสอบแล้วด้วยเบราว์เซอร์จำลอง 7 ขนาด (320, 375, 412, 768, 1024, 1366, 1920px) ทุกหน้าไม่มีเนื้อหาล้นจอ — **ยังไม่ได้ทดสอบบนเครื่องจริง** (โดยเฉพาะ iPhone/Safari และ Android รุ่นเก่า) ควรลองเปิดบนเครื่องของผู้ทดสอบก่อนเปิดใช้

## 4. วิธีใช้งานระบบ
### 4.1 ผู้ดูแลระบบ (ทำก่อนเปิดให้คนอื่นใช้)
1. ให้เจ้าหน้าที่ **เข้าสู่ระบบมาแล้วอย่างน้อย 1 ครั้ง** (จะได้บทบาทผู้แจ้งก่อน)
2. เมนู **จัดการผู้ใช้** → หาอีเมลของเจ้าหน้าที่ → เปลี่ยนช่องบทบาทเป็น **เจ้าหน้าที่** (บันทึกอัตโนมัติ) · ตั้งผู้ดูแลเพิ่มได้ด้วยการเลือก **ผู้ดูแลระบบ**
3. เมนู **บันทึกกิจกรรม** ดูประวัติการเปลี่ยนสถานะ/มอบหมายงาน
4. เมนู **สรุปข้อมูลและสถิติ** ดูภาพรวม และ **แผนที่จุดปัญหา** ดูหมุดตามอาคาร

### 4.2 ผู้แจ้ง (นักศึกษา/บุคลากร)
1. เมนู **แจ้งปัญหาใหม่** → เลือก **ประเภทปัญหา** (เลือก “อื่น ๆ” แล้วพิมพ์เองได้) → เลือก **อาคาร** → พิมพ์ **ห้อง/จุด** (พิมพ์รหัสจุดบนแผนที่ เช่น `A3` หมุดจะอยู่ตรงจุดนั้น ถ้าพิมพ์อย่างอื่นหมุดจะอยู่ที่จุดแรกของอาคาร) → ใส่ **รายละเอียด** → แนบรูป JPG/PNG ได้สูงสุด 3 รูป (ระบบย่อให้เอง) → **ส่งข้อมูลแจ้งปัญหา**
2. จะได้เลขที่ Ticket เช่น `FX-XXXXXXX` ติดตามได้ที่ **ติดตามสถานะ** / **รายการแจ้งปัญหา** กดแถวเพื่อดูไทม์ไลน์: รอตรวจสอบ → รับเรื่องแล้ว → กำลังดำเนินการ → แก้ไขแล้ว
3. เมนู **การแจ้งเตือน** แสดงความคืบหน้าและข้อความขอข้อมูลเพิ่มจากเจ้าหน้าที่ (จะส่งอีเมลด้วยถ้าตั้ง SMTP)
4. ถ้าสถานะเป็น “แก้ไขแล้ว” แต่ปัญหายังอยู่ กด **ปัญหายังไม่หาย · เปิดเรื่องซ้ำ** (ทำได้ภายใน 7 วัน) หลังจากนั้นให้แจ้งเรื่องใหม่
5. **กรณีฉุกเฉิน** (ไฟไหม้ ไฟรั่ว น้ำท่วมใหญ่ มีผู้บาดเจ็บ) อย่าใช้ระบบนี้ ให้โทรหน่วยฉุกเฉินของมหาวิทยาลัย *(ต้องแก้ข้อความ/เบอร์ในหน้าแจ้งปัญหาให้เป็นของจริงก่อนใช้งานจริง)*

### 4.3 เจ้าหน้าที่
1. เมนู **จัดการ Ticket** → กรองตามสถานะ → กด **ดำเนินการ** ที่ Ticket ที่ต้องการ
2. ในหน้ารายละเอียด ส่วน “การดำเนินงาน”: เลือก **ผู้รับผิดชอบ** (ต้องเลือกก่อนเปลี่ยนสถานะ) → กดปุ่มลูกศร (เช่น “→ รับเรื่องแล้ว”) เพื่อเลื่อนสถานะทีละขั้น ข้ามขั้นไม่ได้
3. ขั้นสุดท้าย “→ แก้ไขแล้ว” **ต้องกรอกบันทึกผลการแก้ไข** ผู้แจ้งจะได้รับแจ้งเตือนพร้อมข้อความนั้น
4. ถ้าข้อมูลไม่พอ กด **ขอข้อมูลเพิ่มจากผู้แจ้ง** (พิมพ์ข้อความในช่องบันทึกก่อนได้)
5. หากมีคนอื่นเปลี่ยนสถานะ Ticket เดียวกันไปก่อน ระบบจะแจ้งให้รีเฟรช

### 4.4 ตารางสิทธิ์
| | ผู้แจ้ง | เจ้าหน้าที่ | ผู้ดูแลระบบ |
|---|---|---|---|
| แจ้งปัญหา / ดู Ticket ของตนเอง / เปิดซ้ำ | ✔ | ✔ | ✔ |
| ดูทุก Ticket, รับงาน, มอบหมาย, ปิดงาน | ✘ | ✔ | ✔ |
| จัดการผู้ใช้, ดูบันทึกกิจกรรม | ✘ | ✘ | ✔ |

## 5. แก้ปัญหาที่พบบ่อย
| อาการ | สาเหตุ / วิธีแก้ |
|---|---|
| `npm run dev` ขึ้น “Cannot find .env” หรือรันไม่ได้ | ยังไม่ได้สร้างไฟล์ `.env` (ข้อ 2.2) หรือ Node เก่ากว่า 20.6 (`node -v`) |
| พอร์ต 3000 ถูกใช้อยู่ | แก้ `PORT=3001` ใน `.env` |
| ขึ้น “ตั้งค่าไม่ครบ: …” | อ่านข้อความ มันบอกชื่อตัวแปรที่ขาด/สั้นเกินไป (`PILOT_CODE` ≥ 8, `SESSION_SECRET` ≥ 32, ต้องมี `DATABASE_URL`, `ADMIN_EMAILS`) |
| Vercel ขึ้น “ระบบยังตั้งค่าไม่ครบหรือเชื่อมฐานข้อมูลไม่ได้” | Vercel → Deployments → ล่าสุด → Functions/Logs ดูข้อความ แล้วตรวจตัวแปร + Redeploy |
| เชื่อมฐานข้อมูลไม่ได้ / password authentication failed | รหัสผ่านใน `DATABASE_URL` ผิดหรือไม่ได้ URL-encode · ใช้สตริงแบบ Pooler ไม่ใช่ “Direct connection” |
| ขึ้น relation "users" does not exist | ยังไม่ได้รัน `db/schema.sql` ใน Supabase (ขั้น A ข้อ 3) |
| “รหัสเข้าร่วมไม่ถูกต้อง” | ตรวจ `PILOT_CODE` ตรงกับที่พิมพ์ (แยกตัวพิมพ์ใหญ่เล็ก) |
| “ลองเข้าสู่ระบบบ่อยเกินไป” | ใส่ผิดเกิน 10 ครั้ง รอ 15 นาที |
| เข้าได้แต่ไม่เห็นเมนูผู้ดูแล | อีเมลที่ใช้ไม่ตรงกับ `ADMIN_EMAILS` (ตัวสะกดต้องตรง) แก้ตัวแปรแล้ว Redeploy และเข้าสู่ระบบใหม่ |
| ขึ้น “ไม่มีสิทธิ์” เมื่อเจ้าหน้าที่เปลี่ยนสถานะ | บทบาทยังเป็นผู้แจ้ง ให้ผู้ดูแลตั้งที่เมนู จัดการผู้ใช้ แล้วให้เจ้าหน้าที่ออกจากระบบ-เข้าใหม่/รีเฟรช |
| แนบรูปไม่ได้ | รองรับเฉพาะ JPG/PNG ไม่เกิน 5 MB ต่อไฟล์ และไม่เกิน 3 รูป |
| ไม่มีอีเมลแจ้งเตือน | ต้องตั้ง `SMTP_URL` ไม่เช่นนั้นระบบแค่บันทึกใน log (แจ้งเตือนในแอปยังใช้ได้) |

## 6. การดูแลระบบ
- **สำรองข้อมูล:** ตั้ง `DATABASE_URL` ในเทอร์มินัลแล้วรัน `npm run backup` ได้ไฟล์ JSON ในโฟลเดอร์ `backups/` (รวมรูป) เก็บไว้นอกเครื่อง/นอก repo — ควรทำก่อนจบรอบทดสอบ Supabase มีระบบสำรองของตัวเองด้วย (ขึ้นกับแพ็กเกจ)
- **ลบข้อมูลเก่าตามนโยบาย:** `RETENTION_DAYS=365 npm run purge`
- **ตั้งผู้ดูแลจากเทอร์มินัล:** `node scripts/make-admin.js อีเมล`
- **เปลี่ยนรหัสเข้าร่วม:** แก้ `PILOT_CODE` ใน Vercel แล้ว Redeploy (ผู้ที่เข้าแล้วยังใช้ได้จนครบ 8 ชั่วโมง)
- **จบรอบทดสอบ:** ลบ/เปลี่ยน `PILOT_CODE` หรือหยุดโปรเจกต์บน Vercel เพื่อไม่ให้คนนอกเข้า
- **อัปเดตระบบ:** แก้โค้ด → `git add . && git commit -m "…" && git push` Vercel deploy ให้ ถ้าเปลี่ยนโครงสร้างตาราง ให้รัน SQL ใหม่ใน Supabase ก่อน
- ข้อจำกัดโควตาฟรีของ Supabase/Vercel: โปรเจกต์ที่ไม่มีคนใช้นานอาจถูกพัก แผน Hobby ของ Vercel ใช้ได้เฉพาะงานที่ไม่ใช่เชิงพาณิชย์

## 7. ก่อนใช้กับข้อมูลจริงของมหาวิทยาลัย
สถานะปัจจุบันคือ **โหมดทดสอบ** (ล็อกอินด้วยรหัสร่วม) ยังไม่เหมาะกับข้อมูลจริง ต้องทำเพิ่ม:
1. **เชื่อมบัญชีมหาวิทยาลัย (SSO)** ร่วมกับฝ่าย IT: ตั้ง `AUTH_MODE=proxy` + `PROXY_SECRET` + `ALLOWED_EMAIL_DOMAIN` ให้ reverse proxy ของมหาวิทยาลัย (เช่น oauth2-proxy, Shibboleth) ยืนยันตัวตนแล้วส่ง header `X-Forwarded-Email`, `X-Forwarded-User`, `X-Proxy-Secret` (proxy ต้องลบ header เหล่านี้ที่มาจากผู้ใช้ก่อน และแอปต้องเข้าถึงได้ผ่าน proxy เท่านั้น) *— ส่วนนี้ยังไม่ได้ทดสอบกับระบบจริง*
2. **PDPA:** ข้อมูลอยู่บน Supabase/Vercel (ต่างประเทศ) ต้องมีประกาศความเป็นส่วนตัว และปรึกษาเจ้าหน้าที่คุ้มครองข้อมูลเรื่องการส่งข้อมูลไปต่างประเทศ
3. **ยืนยันข้อมูลกับหน่วยงาน:** เบอร์ฉุกเฉิน, ผู้รับผิดชอบแต่ละทีม, เวลา SLA, ชื่ออาคาร/ห้องจริง
4. ทดลองใช้กลุ่มเล็ก ทดสอบบนมือถือจริงหลายรุ่น ก่อนเปิดเต็มรูปแบบ
5. **ยังไม่ได้ทดสอบกับ Supabase/Vercel จริง** (ทดสอบกับ PostgreSQL จำลองในเครื่อง) — หลัง deploy ให้ลองแจ้ง/รับงาน/ปิดงานด้วย 2 บัญชีเสมอ

**มาตรการความปลอดภัยในโค้ด:** ตรวจสิทธิ์ฝั่งเซิร์ฟเวอร์ · กัน CSRF · จำกัดอัตราคำขอ (เก็บใน Postgres) · SQL แบบ parameterized · ตรวจไฟล์รูปด้วย magic bytes · รูปเข้าถึงได้เฉพาะเจ้าของ/เจ้าหน้าที่ · CSP · escape ข้อความผู้ใช้ · บันทึกกิจกรรมใน `audit_logs` · เปิด RLS ทุกตาราง

## ภาคผนวก: รันด้วย Docker / เซิร์ฟเวอร์ของตัวเอง
```
docker build -t fixu .
docker run -d --name fixu --env-file .env -p 127.0.0.1:3000:3000 fixu
```
ใช้ตัวแปรชุดเดียวกับตาราง Vercel (ตั้ง `NODE_ENV=production`) และวางไว้หลัง HTTPS reverse proxy · `GET /healthz` ใช้ตรวจสุขภาพ
